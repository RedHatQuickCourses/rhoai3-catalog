Making the RHOAI Model Catalog Work for You

The Model Catalog: Operationalizing Model Selection

Standardize the selection process. Validate performance before deployment. Operationalize artifacts via OCI.

For Platform Engineers, the challenge of Generative AI is not model discovery—it is model curation. Allowing ad-hoc downloads of arbitrary weights from public hubs introduces significant operational risks: incompatible hardware requirements, unverified performance on specific accelerators, and inefficient artifact distribution ("Shadow AI").

In Red Hat OpenShift AI (RHOAI), the Model Catalog functions as a centralized control plane to solve these integration challenges. It provides a library of Red Hat Validated Models—curated, benchmarked, and packaged to ensure predictability in enterprise environments.

This guide outlines how the Model Catalog accelerates the path from "selection" to "serving" by providing performance baselines, hardware-aligned quantization, and standardized deployment mechanics.

1. Validated Performance (Risk Reduction)

The primary value of the Model Catalog is the removal of integration guesswork. Unlike public repositories where models are uploaded "as-is," the Red Hat Validated Models available in the catalog undergo a rigorous qualification process using tools like GuideLLM and vLLM.

  • Hardware Alignment: Models are explicitly verified to run on specific accelerator profiles (e.g., NVIDIA A100/H100, AMD MI300).

  • Performance Baselines: Red Hat provides metrics for throughput and latency, allowing you to evaluate if a model fits your Service Level Objectives (SLOs) before you commit resources.

  • Quantization Clarity: The catalog provides specific quantized variants (e.g., w4a16, w8a8, FP8) to match your available VRAM. This prevents the common failure mode of deploying a 70B parameter model to a GPU that physically cannot hold its weights.

2. Optimized Artifact Delivery (ModelCars)

Operational efficiency depends on how massive model weights are distributed to your cluster. The Model Catalog prioritizes ModelCars—models packaged as OCI (Open Container Initiative) artifacts stored in enterprise registries (like registry.redhat.io).

Using ModelCars enables standard container workflow benefits for Large Language Models:

  • Layer Deduplication: Reduces storage costs and network bandwidth when deploying updated versions of the same model family.

  • Faster Startup: Leveraging container image pull secrets and node-level caching significantly improves "Time-to-Ready" for inference services compared to downloading raw object files at runtime.

  • Security & Governance: You can apply standard container scanning and signing policies to model artifacts, treating them exactly like software binaries.

3. The Deployment Wizard: Reducing Configuration Drift

Manually configuring KServe InferenceServices requires precise alignment between the serving runtime, storage URI, and resource requests. The Model Catalog includes a deployment wizard that automates this configuration to prevent drift.

  • Sensible Defaults: The wizard pre-populates runtime arguments and environment variables known to work for the specific model variant.

  • Hardware Profile Integration: It automatically filters for compatible hardware profiles, preventing deployments that are destined to fail due to resource mismatches.

  • Repeatability: It enforces a standardized deployment structure, ensuring that every engineer on the team deploys models using the same architectural pattern.

Context: Catalog vs. Registry

While similar in name, these components serve distinct phases of the lifecycle:

  • The Model Catalog is for Inbound Discovery: Bringing third-party, validated assets (like Red Hat Validated Models) into your environment.

  • The Model Registry is for Outbound Control: Versioning and governing the proprietary models your team creates, tunes, or adopts for the long term.

What You Will Learn

This module is designed to help you operationalize the Model Catalog within your RHOAI environment. You will learn to:

  1. Navigate the Architecture: Understand how the catalog sources data and how it integrates with ModelCars (OCI).

  2. Deploy with Precision: Use the deployment wizard to launch a validated model (e.g., Granite, Mistral), ensuring correct alignment of hardware profiles and runtimes.

  3. Configure & Curate: Administer the catalog by managing ConfigMap sources to control which models are visible to your users.

  4. Troubleshoot: Address common operational constraints, such as Kubernetes naming limits and storage configuration issues.
