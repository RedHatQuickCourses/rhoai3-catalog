Simulator: The Catalog Experience

See the end state before you build the supply chain.

Before we drop into the terminal to manipulate ConfigMaps and SourceURIs, it is critical to understand what the "Consumer" (the AI Engineer or Data Scientist) actually experiences.

In this interactive simulation, you will walk through the Red Hat OpenShift AI Model Catalog from the perspective of a user trying to find and deploy a compliant model.

The Interactive Walkthrough

Instructions

Click "Get Started" in the window below. Follow the on-screen prompts to navigate the catalog filters, inspect a ModelCard, and launch the Deployment Wizard.

Key Observations

As you clicked through the simulation, did you notice the following operational details?

1. The "Provider" Filter

  • Observation: In the sidebar, you saw options for "Red Hat," "Hugging Face," and "Community."

  • The Backend Reality: Each of these checkboxes corresponds to a specific entry in the model-catalog-sources ConfigMap. When you uncheck "Community," you are essentially filtering the JSON array returned by the catalog API.

2. The Model Card "Source"

  • Observation: When you opened the Granite 7B card, the "Source" field displayed registry.redhat.io.

  • The Backend Reality: This confirms the asset is a ModelCar (OCI artifact). If you had selected a community model, this field would likely show a huggingface.co URL, indicating a raw file download.

3. The Hardware Profile Match

  • Observation: In the Deployment Wizard, the "Hardware Profile" dropdown was pre-selected or filtered.

  • The Backend Reality: The catalog metadata includes a hardware_profile tag. The wizard uses this to query the cluster for NodeResources. If your cluster lacked GPUs, that dropdown would be empty, and the deployment would be blocked—protecting you from a pending pod failure.
