A catalog that doesn’t load delivers zero value. A catalog that works delivers a competitive advantage.

You have built the supply chain. You have learned how to inject custom sources and deploy with hardware-aligned profiles. Now, we turn to Day 2 Operations: keeping the lights on and articulating the value of what you have built.

1. Managing Availability (The "Kill Switch")

There will be times—during upgrades, security audits, or huge re-indexing operations—when you need to temporarily close the showroom. You control visibility via the OdhDashboardConfig resource.

To hide the catalog from the UI:

oc patch odhdashboardconfig odh-dashboard-config \
  -n redhat-ods-applications \
  --type merge \
  -p '{"spec": {"dashboardConfig": {"disableModelCatalog": true}}}'

  • True: Catalog tab disappears.

  • False: Catalog tab reappears.

2. The Troubleshooting Playbook (RHOAI 3.2)

Even a validated platform has edge cases. These are the three most common "Gotchas" you will encounter as a Platform Engineer, and exactly how to fix them.

Issue A: The Upgrade Hang

  • Symptom: After an OpenShift AI upgrade, the Catalog UI is blank or displays "Request access to model catalog."

  • Root Cause: The model-catalog-sources ConfigMap schema changed, and the operator failed to reconcile the old state.

  • The Fix: Force a clean regeneration.

# Delete the config and the pod; the operator will recreate them with defaults
oc delete configmap model-catalog-sources -n rhoai-model-registries
oc delete pod -l component=model-catalog -n rhoai-model-registries

Issue B: The "Missing Storage" Loop

  • Symptom: In the Deployment Wizard, the "Existing Cluster Storage" radio button is hidden, forcing you to create a new connection even if you already have PVCs.

  • Root Cause: The Wizard UI logic proactively hides the option if it detects zero DataConnections in the project.

  • The Fix:

    1. Go to Settings → Data Connections.

    2. Create a "Dummy" S3 connection (it doesn’t need to be real).

    3. Refresh the Wizard. The "Existing Cluster Storage" option will appear.

Issue C: DNS Name Collisions (The 63-Char Limit)

  • Symptom: Deployment status hangs in "Unknown" or fails with internal service errors.

  • Root Cause: You accepted a long default name (e.g., mistral-7b-instruct-v0.1-quantized-w4a16). KServe appends suffixes (e.g., -predictor-default), pushing the string over the Kubernetes 63-character DNS label limit.

  • The Fix: Always rename. Use short aliases like mistral-7b-prod.

3. Operational Guardrails Summary

To keep your catalog healthy, commit to these three rules:

  1. Prefer ModelCars: Ensure your cluster has pull secrets for registry.redhat.io . This moves model distribution from "slow file downloads" to "fast container caching."

  2. GitOps Your Sources: Never edit the model-catalog-sources ConfigMap manually in production. Manage it in Git so you have an audit trail of every model added or removed.

  3. Quantization Matching: Monitor your ClusterResourceQuotas. Ensure you aren’t approving .FP8 models (High Performance) if your nodes only have older GPUs that can only handle .w4a16 (High Efficiency).

4. The Payoff: Business Value & ROI

You started this course with a question: "Why should we use this instead of just downloading files from the internet?"

You now have the answer. The Model Catalog is not just a UI; it is a Risk Control Plane.

Value Pillar The Engineering Reality

1. ROI & Cost

Quantization Aware: By filtering for .w4a16 or .w8a8 models, you fit 70B parameter models onto cheaper GPUs (e.g., A10g vs A100), potentially lowering hardware TCO by 40-60%.

2. Security

Supply Chain Trust: Red Hat Validated Models are scanned and signed. You aren’t pulling "mystery weights" containing pickled malware or unknown licenses.

3. Performance

Hardware Validated: You don’t waste weeks discovering a model is incompatible with your accelerator. If it’s in the catalog with a profile, it runs.

4. Speed

ModelCars: OCI-based delivery means scaling out 10 replicas takes seconds (cached layers) rather than minutes (re-downloading 50GB files).
