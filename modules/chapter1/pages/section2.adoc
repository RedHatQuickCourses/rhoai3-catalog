:description: Hands-on guide to registering a private model source in the RHOAI Model Catalog using CLI and ConfigMaps.

[.lead]
*We don't click buttons to add infrastructure. We apply code.*

In this lab, you will simulate the workflow of a Platform Engineer at "Acme Corp." Your data science team has fine-tuned a model (`Acme-Finance-7B`) and stored it in a private S3 bucket.

Your task is to register this private model into the global **Model Catalog** so that authorized developers can deploy it using the standard wizard—without them knowing (or caring) that it comes from a private bucket.

== Prerequisites
* Access to the cluster with `cluster-admin` (or edit rights in `rhoai-model-registries`).
* The `oc` CLI tool.

== Step 1: Define the Catalog Manifests

We need to construct two objects to inject into the `model-catalog-sources` ConfigMap:
1.  **The Source Registration:** Tells the catalog *where* to look for metadata.
2.  **The Model Metadata:** The actual card data (Architecture, Quantization, URI).

Run the following command in your terminal to create the catalog definition file locally:

[source,bash]
----
cat <<EOF > acme-catalog.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: model-catalog-sources
  namespace: rhoai-model-registries
  labels:
    model.catalog.sources: "true"
data:
  # 1. Register the new "file" source
  sources.yaml: |
    sources:
      - name: acme-corp-private
        displayName: "Acme Corp Private Models"
        description: "Internal fine-tuned models for Finance and HR applications."
        sourceURI: "file:///etc/model-catalog-source/acme-models.yaml"

  # 2. Define the Model Metadata (The "Card")
  acme-models.yaml: |
    apiVersion: modelregistry.opendatahub.io/v1alpha1
    kind: ModelRegistry
    metadata:
      name: acme-finance-7b
    spec:
      models:
        - name: "Acme-Finance-7B"
          displayName: "Acme Finance 7B (v1.2)"
          description: "Fine-tuned on quarterly reports. Optimized for summarization."
          provider: "Acme AI Lab"
          version: "1.2.0"
          tags: ["finance", "summarization", "internal"]
          
          # The Critical Part: Pointing to Private Storage
          model_files:
            - name: "safetensors-w4a16"
              size: "4GB"
              quantization: "w4a16"
              uri: "s3://acme-private-models/finance-7b/v1.2/"
          
          # Hardware Requirements (The Guardrails)
          hardware_profile:
            - "nvidia.com/gpu" 
EOF
----

[NOTE]
.The "Industrialized" Concept
====
In a real production environment, this `acme-models.yaml` would likely be a file in a Git repository. The `sources.yaml` would point to that Git URL (e.g., `https://github.com/acme/catalog/archive/main.zip`).

For this lab, we are using the `file://` protocol to inject the metadata directly into the ConfigMap for immediate feedback.
====

== Step 2: Apply the Configuration

Inject the new configuration into the cluster. This overwrites the existing ConfigMap with your new definition.

[source,bash]
----
oc apply -f acme-catalog.yaml
----

*Expected Output:*
`configmap/model-catalog-sources configured`

== Step 3: Force a Catalog Refresh

The Model Catalog service caches the configuration on startup. To see your changes immediately, you must restart the pod.

[source,bash]
----
# 1. Delete the existing pod to force a rollout
oc delete pod -l component=model-catalog -n rhoai-model-registries

# 2. Wait for the new pod to be Ready
oc wait --for=condition=Ready pod -l component=model-catalog -n rhoai-model-registries --timeout=60s
----

== Step 4: Verification (The "Arcade" Moment)

Now that the backend is configured, the frontend should reflect the new reality.

1.  Open the **OpenShift AI Dashboard**.
2.  Navigate to **Model Catalog**.
3.  In the **Provider** filter on the left, you should now see a new checkbox: **"Acme AI Lab"**.
4.  Select it. You will see the **"Acme Finance 7B"** card.
5.  Click the card. Verify that the **Model Location** points to your private S3 URI (`s3://acme-private-models...`).
