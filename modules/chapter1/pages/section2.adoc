= Lab: Customizing the Catalog
:navtitle: Lab: Customizing the Catalog
:toc: macro

// Antora metadata
:page-role: hands-on-lab
:description: How to inject private models into the RHOAI Model Catalog using the embedded ConfigMap strategy for air-gapped stability.

[.lead]
*This custimization method involes embedding the catalog selction directly in the configmap.*

In strict enterprise environments, you often cannot point your Model Catalog to a public GitHub URL or an external HTTP server. The cluster might be air-gapped, or the firewall might block the request.

The most robust way to add a custom source is the **"Embedded Strategy"**.

In this lab, you will configure the `model-catalog-sources` ConfigMap to serve two roles simultaneously:

 1.  **The Pointer:** It defines *where* to look for models.
 2.  **The Database:** It contains the actual model metadata itself.

== Procedure

=== 1. Switch to the Registry Namespace

First, ensure you are working in the correct namespace where the Model Registry components are running.

[source,bash]
----
oc project rhoai-model-registries
----

=== 2. Open the Catalog Configuration

The Model Catalog does not use a database for configuration; it uses a Kubernetes **ConfigMap**. You will edit this object directly.

[source,bash]
----
oc edit configmap model-catalog-sources
----

[NOTE]
====
You are editing a **ConfigMap**, not a local file. The file `sources.yaml` exists virtually inside the `data` section of this object.
====

=== 3. Configure the Registry and Add Models

You need to define two logical "files" inside this ConfigMap:

 1.  **`sources.yaml`**: Registers your custom catalog path.
 2.  **`my-models.yaml`**: Contains the actual metadata for your models.

Copy and paste the following data segment of the block into the `data:` section of the ConfigMap.

.Understanding the Schema
* **Top-Level Fields:** Only `name`, `description`, `readme`, and `maturity` are allowed here.
* **customProperties:** You **must** put `author`, `version`, `model_type`, and other metadata here to avoid errors.

[source,yaml]
----
cat <<EOF > private-catalog.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: model-catalog-sources
  namespace: rhoai-model-registries
  labels:
    model.catalog.sources: "true"
data:
  # KEY 1: The Registration (The "Pointer")
  # This tells the catalog app to look at a local file for the actual inventory.
  sources.yaml: |
    sources:
      - name: acme-corp-private
        displayName: "Acme Finance 7B (v1.2)"
        description: "Internal fine-tuned models for Finance and HR applications."
        properties:
          yamlCatalogPath: "/data/user-sources/acme-models.yaml"

  # KEY 2: The Inventory (The "Database")
  # This key contains the actual ModelRegistry definition. 
  # Because of the volume mount, this key becomes the file referenced above.
  acme-models.yaml: |
    models:
      # --- MODEL 1: Qwen/Qwen3-0.6B ---
      - name: "Qwen3-0.6B"
        provider: "Acme AI Lab"
        description: "Qwen Small Language Model"
        customProperties:
          model_type:
            metadataType: MetadataStringValue
            string_value: "generative"
          author:
            metadataType: MetadataStringValue
            string_value: "Qwen"
          version:
            metadataType: MetadataStringValue
            string_value: "1.2.0"
        artifacts:
          - name: "model-artifact"
            uri: "s3://private-models/Qwen3-0.6B"
----

[IMPORTANT]
.YAML Indentation Warning
====
Notice the structure above. The `acme-models.yaml` content is a **string block** (using `|`) inside the `data` section. Ensure the indentation of the inner YAML is preserved exactly as shown, or the catalog parser will fail.
====

=== 4. Save and Exit

* **Vi/Vim Users:** Press `Esc`, then type `:wq` and press `Enter`.
* **Nano Users:** Press `Ctrl+O`, `Enter`, then `Ctrl+X`.



== Step 5: Verification

1.  Open the **OpenShift AI Dashboard**.
2.  Navigate to **AI Hub -> Model Catalog**.
3.  Look at the **Provider** filter on the left sidebar.
    * *Success:* You see a new checkbox: **"Acme AI Lab"**.
4.  Select the **"Acme AI Lab"** provider.
    * *Success:* The **Acme Finance 7B** card appears.
5.  Click the card.
    * *Success:* The **Model Location** field displays `s3://acme-private-models...`.

== Troubleshooting

If the catalog fails to load or shows "No models found":

1.  **Check the logs:** The catalog pod logs will explicitly state if it failed to parse the YAML.
    [source,bash]
    ----
    oc logs -l component=model-catalog -n rhoai-model-registries
    ----
    *Look for:* `yaml.scanner.ScannerError` (indicates an indentation issue in your ConfigMap).

2.  **Verify the Mount:** Ensure the file actually exists inside the pod.
    [source,bash]
    ----
    oc exec -n rhoai-model-registries -it $(oc get pods -n rhoai-model-registries -l component=model-catalog -o jsonpath='{.items[0].metadata.name}') -- ls -l /etc/model-catalog-source/
    ----
    *Expected:* You should see both `sources.yaml` and `acme-models.yaml`.
